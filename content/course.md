## Who this course is for

You arrive with analytical skills. Earlier courses have introduced you to some
combination of coding, statistics, analytics, business intelligence and machine
learning, and you have used them to answer questions and present results.

DCM asks the next question:

> **Can someone else understand, check, reproduce and use your work?**

That question is harder than it sounds. It is also the question that separates an
interesting analysis from a result an organisation can act on.

## What changed, and what did not

Generative AI now produces a great deal of code, SQL, tests, documentation and
even whole small applications. That genuinely changes where your effort goes.

| You have practised | DCM adds emphasis on |
| --- | --- |
| Writing code | Specifying, inspecting and modifying code |
| Learning syntax | Reasoning about data, logic and systems |
| Producing an answer | Testing the result and its assumptions |
| Working in a script or notebook | Sharing a reproducible project |
| Completing an analysis | Delivering something others can use |

<div class="key">
Code production is increasingly AI-assisted. Code literacy and engineering
judgement are what make the output trustworthy — and they stay yours.
</div>

This is not a course against writing code, and it is not a prompt-engineering
course. You will read more code than you have before, and you will be asked to
explain and defend all of it, whoever or whatever typed it first.

## The four stages

The semester moves through four connected stages, shown in the map above. They
are organising themes rather than sealed units: Git, validation and testing start
early and recur throughout.

**AI is not a fifth stage.** It runs horizontally through all four: explaining,
debugging, generating, refactoring, testing, reviewing and building, with the
amount of assistance growing as your ability to supervise it grows. See
[AI &amp; responsible use](#/ai).

## How a session works

Teaching is on **Thursdays, 09:15–11:00**, in **Anthropole / 3032** — two
45-minute academic periods with a short break between them. The first period is
normally concept and demonstration; the second is hands-on work on your own
machine, which is where most of the learning happens. Bring a laptop if you can;
one laptop per pair is workable.

There is no separate practical session and no teaching assistant this year, so
practice is folded into the same slot. That makes the preparation matter: come
with a working environment and, where indicated, the short preparation for the
week.

Two sessions are different:

- **17 September** — special workshops; no normal DCM class.
- **22 October** — *Responsible AI at UNIL*, delivered asynchronously.

## Python and R

The course uses **both Python and R**. Python is the default language for live
demonstrations and checks, because it keeps the classroom setup small. R remains
fully supported and is often the better choice for a project.

You are **not** expected to implement every exercise twice. Pick the language
that suits the task and the team, and be able to read the other one — reading
code you did not write, in a language you use less, is exactly the literacy this
course is about.

## Assessment in one line

Two individual homeworks at **25%** each and a group project at **50%**.
There is no final exam. See [Assignments](#/assignments) and [Project](#/project).
