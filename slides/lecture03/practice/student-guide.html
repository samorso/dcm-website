  2. Explain why the combined case precedes the separate cases.
  3. Change only the loop bound so it includes 21. Predict, run and check the last output.
  4. Explain the change to a partner. Use one language.

Python · live route

for i in range(1, 21):
    if i % 15 == 0: print("FizzBuzz")
    elif i % 3 == 0: print("Fizz")
    elif i % 5 == 0: print("Buzz")
    else: print(i)

R alternative

for (i in 1:20) {
  if (i %% 15 == 0) cat("FizzBuzz\n")
  else if (i %% 3 == 0) cat("Fizz\n")
  else if (i %% 5 == 0) cat("Buzz\n")
  else cat(i, "\n")
}
FizzBuzz checks — after the attempt

3 → Fizz; 5 → Buzz; 15 → FizzBuzz. Testing the multiple-of-3 condition first would incorrectly label 15 as Fizz. For the bound edit, Python uses range(1, 22) and R uses 1:21. The final output is Fizz at 21; the original final output at 20 was Buzz.

Assumptions, errors and warnings

The required division exercise takes ordinary finite real scalar inputs: one number per argument. Negative values and a zero numerator are valid. We also explicitly test text as invalid input. Arrays, vector recycling/broadcasting, complex/Boolean inputs and pre-existing missing/non-finite values are outside this exercise. This is not a general numeric-validation library.

An error stops the current operation. A warning ordinarily permits execution to continue, but does not establish that the returned result is safe. Try the supplied warning example in a fresh session:

Python · live route

import warnings
warnings.warn("Check the inputs")
print("Execution continues")

R alternative

warning("Check the inputs")
print("Execution continues")

The original my_div(2, 0) raises ZeroDivisionError in Python and returns Inf in R. Neither is a language bug. Later we introduce a new desired contract: missing result plus useful warning when the denominator is zero. Returning missing is a chosen policy, not an automatic cure for every problem.

A data-analysis reason for the policy

Average revenue per order is revenue / number_of_orders. Store A has revenue 1000 and 50 orders: average 20. Store B has revenue 0 and 0 orders: no per-order average is defined. Zero would suggest an observed average; infinity would also mislead. For this exercise we choose a warning plus a missing numeric result. Original my_div(0, 0) raises a Python error or returns R NaN; original (2, 0) returns R Inf. These are language rules, not bugs.

Python math.nan is a floating-point NaN; None is not a numeric NaN. R NA marks a missing/unknown value; NA_real_ is its numeric (double) form. R NaN marks an undefined numerical result. is.na detects both, so our check also excludes NaN. Detecting missing is separate from choosing this policy.

Debugging workflow

Reproduce → locate → hypothesize → change one thing → rerun → verify.

Apply it to f(2) and my_div("a", 2), which you already know:

  • Record intended behavior, the exact input and actual output/error.
  • Identify the error type/message (if any), the relevant operation in your own code and the actual arguments. Here text reaches the division operation.
  • Form a hypothesis before editing. None after f(2) suggests that computation did not become a returned value; it is not an exception.
  • Inspect the small edit, rerun the original case and check other valid inputs.

No debugger software is needed. Preserve a small reproducible example rather than relying on objects or old function definitions left over in your session.

Manual division

10 minutes including debrief; no AI yet. Work on your supplied my_div.

  1. Run my_div("a", 2) and identify the error message, operation and actual inputs.
  2. Insert the supplied guard below inside the function, before division. Read it as “is either argument text?”. Python indentation is part of the block; R uses braces. Do not silently convert text to missing.
  3. Reload your edited function. Check (4,2) → 2, (0,2) → 0, (-4,2) → -2. Each should complete without a warning. Check text in each position separately: my_div("a", 2) and my_div(2, "a") must raise useful errors.
  4. Predict and observe (2,0) separately. Do not add zero handling yet.

These guards reject text; they are not checks of every excluded input domain.

math.isnan(...) should be true in Python. In R, is.na(result) && !is.nan(result) distinguishes the chosen missing result from NaN. These expressions check the returned value only, not whether a warning occurred. Do not compare missing values with equality. The zero-numerator case catches a check of the wrong argument; the negative case checks valid signed arithmetic; the text case catches overbroad error suppression.

For the final check, restart the interpreter and load your edited file again. Python may suppress repeated warnings from the same location; confirm the warning on the first zero-denominator call in that fresh session. Do not add logging or warning-filter machinery to the student function.

Optional: check the warning separately from the value

A missing result does not prove a warning occurred. First observe the message in a fresh session. If uncertain, these supplied checks capture the signal separately; do not put this checking machinery inside your function.

import math
import warnings
with warnings.catch_warnings(record=True) as signals:
    warnings.simplefilter("always")
    result = my_div(2, 0)
print(math.isnan(result))  # value check
print(len(signals))        # signal check: expect 1
print(str(signals[0].message) if signals else "NO WARNING")
warned <- FALSE
result <- withCallingHandlers(my_div(2, 0), warning = function(w) {
  warned <<- TRUE
  message(conditionMessage(w))
  invokeRestart("muffleWarning")
})
is.na(result) && !is.nan(result)  # value check
warned                           # signal check: expect TRUE

Worked safe division

Open only after your attempt, or for the no-AI fallback after proposing your own small edit. This reuses the historical warning and missing-result policy with an explicit scalar branch. It deliberately does not implement broader domains.

Show the scalar solution

Python uses the math and warnings imports already at the top of the starter. The text guard runs before the zero check. Returning from that zero branch prevents ordinary division from running.

Python · live route

import math
import warnings

def my_div(numerator, denominator):
    if isinstance(numerator, str) or isinstance(denominator, str):
        raise TypeError("numerator and denominator must be numbers, not text")
    if denominator == 0:
        warnings.warn("denominator is 0; returning NaN")
        return math.nan
    return numerator / denominator

R alternative

my_div <- function(numerator, denominator) {
  if (is.character(numerator) || is.character(denominator)) {
    stop("numerator and denominator must be numbers, not text")
  }
  if (denominator == 0) {
    warning("denominator is 0; returning NA")
    return(NA_real_)
  }
  return(numerator / denominator)
}
